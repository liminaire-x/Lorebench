# 0015 — 퀘스트 단계

2026-09-27 · 일곱 번째 이야기(딸에게 가는 목걸이) 설계(구현 전) · 고치는 비용: **비쌈** (퀘스트 문서의 `stages`·`keep`·`gives`,
플레이어 기록 `stage_` 키에 남는다. 첫 공개 전이라 지금은 쌈: 있는 퀘스트는 스크래치 스크립트로 단계 하나짜리로 옮기고,
기록은 "단계 기록 없음 = 첫 단계"라 그대로 읽힌다. 모드 안에 변환 코드는 넣지 않는다)

## 장면

> 경비대장의 부탁으로 늑대에게서 목걸이 조각 셋을 찾아 **보여주면**, 경비대장은 대장장이에게 고쳐 달라고 한다. 대장장이에게
> 조각을 **맡기고 하루 기다려** 고친 목걸이를 **받고**, **경비대장의 딸**에게 전한다. 퀘스트는 하나이고 J 화면의 할 일만 바뀐다.

전체 장면은 [stories.md](../stories.md) "일곱 번째 이야기".

## 퀘스트 = 한 번뿐인 것 + 단계 목록

```json
{ "id": "quest_swomjnmi", "title": "목걸이 찾기", "text": "…", "giver": "npc_ldj9dx60",
  "lines": { "offer": […], "declined": […] },
  "stages": [
    { "id": "stage_a1b2c3d4", "text": "경비대장에게 조각 보여주기", "to": "npc_ldj9dx60",
      "goals": [ { "collect": "…목걸이 조각", "count": 3, "from": "kill:minecraft:wolf", "chance": 0.5, "keep": true } ],
      "lines": { "active": […], "complete": […], "handed": […] } },
    { "id": "stage_e5f6g7h8", "text": "대장장이에게 조각 맡기기", "to": "npc_9j6n9k4a", "wait": { "days": 1 },
      "goals": [ { "collect": "…목걸이 조각", "count": 3 } ],
      "gives": [ { "item": "…고친 목걸이", "count": 1, "quest": true } ],
      "lines": { "complete": […], "handed": […], "waiting": […], "ready": […] } },
    { "id": "stage_i9j0k1l2", "text": "딸에게 목걸이 전하기", "to": "npc_…",
      "goals": [ { "collect": "…고친 목걸이", "count": 1 } ],
      "lines": { "complete": […] } } ],
  "rewards": [ { "item": "minecraft:emerald", "count": 5 } ] }
```

- **퀘스트에 남는 것**(한 번뿐): `id`·`title`·`icon`·`text`(이야기 설명)·`giver`·`requires`·`supplies`·`rewards`·`folder`,
  대사 `offer`·`accepted`·`declined`.
- **단계에 들어가는 것**: `id`, `text`(할 일 한 줄, **꼭 적음**), `to`(갈 NPC, 비우면 주는 NPC: 옛 `receiver` 규칙), `goals`,
  `wait`(0013), `gives`, 대사 `active`·`complete`·`handed`·`waiting`·`ready`. 퀘스트의 `receiver`·`goals`·`wait`는 단계로 옮겨 간다.
- 단계는 **하나 이상**. 지금까지의 퀘스트는 단계 하나짜리다. **모양이 하나**라 코드·에디터·J 화면이 늘 같은 길로 간다.
- **할 일(`goals`)이 없는 단계** = 그 NPC에게 말 걸기.
- 단계는 퀘스트가 아니다: 제안·거절·보상·폴더가 없다(에디터에서도 퀘스트와 구별해 보인다).

## 단계 id와 기록

```
stage_quest_swomjnmi = stage_e5f6g7h8     (주인 = 플레이어, 지금 단계의 id)
```

- 단계 id는 **에디터가 붙이는 무작위 id**(`stage_` + 8자, [0004](0004-ids-and-record-keys.md)). 작가는 `text`만 본다. 그래서 단계를
  **끼우거나 순서를 바꿔도** 진행 중인 사람은 제자리에 있다. id는 문서 전체에서 하나뿐이다.
- 기록 키 `stage_<퀘스트 id>`(0004의 종류 접두사 규칙, `handed_`·`declined_`와 같은 모양).
- **기록이 없으면 첫 단계**(수락 직후, 옛 기록). 기록이 **문서에 없는 단계**를 가리키면 저절로 옮기지 않는다: 그 사람은 멈추고,
  로그와 에디터 Players에 "없는 단계"로 보인다(작가가 [Reset]).
- 상태 기록(`active`/`waiting`/`done`, 0005·0013)은 그대로 **퀘스트 전체의 상태**다. 어느 단계든 진행 중이면 `active`,
  기다림이 있는 단계에서 건넸으면 `waiting` + `handed_`.
- 퀘스트가 끝나면(`done`) `stage_`를 지운다. Players → [Reset]도 지운다.
- 단계가 바뀌면 진행 기록(`progress_`, 처치·수확·번식 수)을 비운다: 다음 단계는 0부터.

## 단계 지우기·옮기기: publish 때 한 번, 엄격하게

- 사람이 있는 단계를 지우고 publish하면 에디터가 묻는다: "`대장장이에게 조각 맡기기`에 2명이 있습니다. 어디로 옮길까요?"
  (같은 퀘스트의 남은 단계 중에서). 답은 **publish 요청에 딸린 한 번의 지시**이고 문서에는 남지 않는다. 서버는 그 순간 기록을
  바꾼다(접속하지 않은 사람 포함, Reset과 같은 방식).
- **옮길 곳이 없거나 그 퀘스트에 없는 단계면 publish 거부**: `'목걸이 찾기' (quest_…): 2 players are on the removed stage
  '대장장이에게 조각 맡기기'; choose where they go`. 검사는 publish 순간의 기록으로 한다(에디터를 연 뒤 넘어간 사람도 잡힌다).
  "모르면 첫 단계로" 같은 기본값은 두지 않는다: 작가 모르게 플레이어를 옮기게 된다.
- 옮긴 사람은 **고른 단계의 처음부터**: 진행은 0, 기다리던 중이었다면 기다림도 없어진다. 이미 건넨 아이템은 돌아오지 않는다(창에 안내).
- 퀘스트를 통째로 지울 때는 0005대로 기록을 남긴다(묻지 않음).
- **다른 퀘스트로 끌어 옮기기** = A에서 지우고 B에 넣기. 놓는 순간 확인 창("A에서 이 단계에 있는 N명은 publish 때 돌아갈 단계를
  골라야 합니다"), publish 때 위의 창. **플레이어는 단계를 따라가지 않는다**(수락하지 않은 B가 진행 중이 되므로). B에서는 **새 id**.
  그 단계가 전용 아이템을 쓰면 "표식이 A의 것이라 B에서는 세지 않습니다"를 창에 덧붙인다.

## 보여주기: 목표의 `keep`

- `"keep": true`인 제출형(`item`)·전용(`collect`) 목표는 [건네기] 때 **가져가지 않는다**. 없으면 지금처럼 가져간다(옛 문서 그대로).
- 목표마다 적는다: 아이템을 가져가는 일이 원래 목표마다 일어나고, 처치 목표에는 가져갈 것이 없다. "편지는 건네고 조각은
  보여주기만"도 된다.
- 단계에서 가져갈 것이 하나도 없으면 버튼이 **[보여주기]**(en "Show"), 하나라도 있으면 [건네기].
  구현(조각 2)에서 좁힘: `keep` 목표가 있고 가져갈 것이 없을 때만 [보여주기]. 처치·수확·번식만 있는 단계도 가져갈 것은
  없지만 "보여주기"가 어색해 지금처럼 [건네기], 할 일이 없는 단계는 [받기](보상 카드가 있을 때).

## 단계가 주는 것 `gives`, 퀘스트의 `rewards`

- `gives`는 **단계가 끝날 때** 준다: 기다림이 있는 단계는 [받기] 때, 없으면 [건네기]·[보여주기] 때. 마지막 단계면 `gives`와
  퀘스트 `rewards`를 함께 준다. 가방에 안 들어가면 발밑(0005).
- 퀘스트 `rewards`는 J 화면에 처음부터 보이고, `gives`(이야기 속 물건)는 받는 순간까지 보이지 않는다(다음 단계는 보내지 않으므로).
- 기본은 **평범한 아이템**(포션, 팔 수 있는 장비, 계속 쓰는 도구). `"quest": true`인 것만 **주인 표식**(0012 모양 그대로, 퀘스트 id)을
  붙인다. 표식이 없으면 나중 단계에서 이름(`item` 조건)으로 세야 하고, 모루로 이름을 바꾼 가짜가 통과한다.

## `collect`의 `from`을 비우면: 이미 가진 것만 셈

- 표식은 **퀘스트** id에 붙으므로, 1단계에서 주운 조각을 2단계가 알아본다. `from`이 없으면 더 떨어지지 않는다.
- 가방에 있는 그대로 따라온다: 1단계에서 `keep`한 조각 3개 → 2단계 `조각 5개(from 늑대)`는 `3/5`에서 시작(이어 모으기), 1단계에서
  건넸으면 `0/3`부터(다시 모으기).
- publish 검사: `from` 없는 `collect`는 **앞 단계**에 같은 아이템의 `from` 있는 `collect`나 `quest: true`인 `gives`가 있어야 한다(얻을
  길이 없으면 영영 못 끝남).
- 0012의 "같은 아이템의 `collect` 둘이면 거부"는 **한 단계 안에서만** 따진다. 단계는 한 번에 하나만 진행되기 때문이다.
- 받아들인 것: `from` 없는 단계에서 조각을 버리면 못 끝낸다. 작가가 그 단계에도 `from`을 적으면 다시 떨어진다. 고친 목걸이처럼
  `gives`로 받은 것을 버리면 Players → [Reset].

## 대사: 단계마다

- 퀘스트: `offer`·`accepted`·`declined`. 단계: `active`(못 끝냈을 때 말 걸면)·`complete`(건네기·보여주기 전)·`handed`·`waiting`·`ready`.
  에디터에서 단계를 펼치면 그 장면의 대사가 위에서 아래로 이야기 순서대로 보인다. 조건 묶음(0012)은 단계의 칸에서도 쓴다.
- **`handed`를 넓힌다**: "건네거나 보여준 직후"(기다림이 없어도). 다음에 어디로 가야 하는지를 여기서 말한다. 기다림이 있는
  단계에서는 0013과 같은 뜻.
- 할 일이 없는 단계: 말 걸면 `complete` → 카드·버튼 없이 다음 단계 → `handed`.
- 단계를 끝낸 뒤 같은 NPC에게 다음 할 일이 있으면 대화가 이어진다(지금 수락·완료 뒤와 같음).

## 그 밖 (쌈·중간)

- **보내는 것**: 지난 단계의 `text` + 지금 단계 전부. **다음 단계는 클라이언트에 보내지 않는다**(자체 퀘스트를 만든 이유와 같은 원칙).
- **J 화면**: 퀘스트 본문 아래 지난 단계를 흐린 줄로, 그 아래 지금 할 일·필요한 것·보상. 전체 단계 수(2/3)는 보이지 않는다.
- **그래프**: `Reveal Quest`는 첫 단계부터(기록 없음 = 첫 단계). `Complete Quest`는 버튼과 같은 한 걸음(마지막 단계면 보상·완료).
  `Quest State` 갈래는 그대로(단계는 안 봄). 중간(그래프에 저장된 갈래는 안 바뀜).
- **에디터**: 사이드바에서 **퀘스트 안에 단계**(번호·다른 아이콘, 작가가 정한 순서, 이름순 정렬 없음). 퀘스트를 누르면 자동으로
  펼쳐진다. **드래그 앤 드롭**으로 순서 바꾸기·다른 퀘스트로 옮기기(위 확인 창). 단계 추가는 **퀘스트 우클릭 메뉴**("단계 추가").
  단계를 누르면 오른쪽에 Text·Go to·Needs(목표마다 Keep)·Wait·Gives(Quest item)·대사. Players에 지금 단계 제목(없는 단계는 빨갛게).
  publish 때 "옮길 곳" 창.
- **메시지 버전**: 퀘스트 목록 5 → 6, 대화 8 → 9.

## 고르지 않은 것

- **지금 모양 그대로 + 필요할 때만 `stages`**: 옛 문서가 읽히는 장점은 첫 공개 뒤에나 값어치가 있고, 모양이 둘인 부담이 남는다.
- **단계마다 짧은 퀘스트 + J 화면에서 묶기**(WoW 잇기, FTB Quests 선): 단계마다 수락·완료 기록이 생기고 다음 단계를 저절로
  시작하는 규칙이 새로 필요하다.
- **단계 순번**(0, 1, 2): 끼우거나 지우면 진행 중인 사람이 다른 단계로 밀린다(이미 건넨 단계로 돌아가 영영 못 끝냄). **작가가 띄운
  번호**(Skyrim 10·20·30): "띄워 쓰라"는 숨은 규칙. **작가가 지은 이름**(Ink knot, Ren'Py label): 이름을 고치면 지우기와 같은 문제.
- **옮김 표를 문서에 남기기**: 기록 DB가 한 곳이라 publish 때 모두 옮길 수 있어, 흔적을 쌓을 이유가 없다.
- **단계에 `keep`**: 처치만 있는 단계에도 뜻 없는 칸이 달린다. **보여주기 없이 저절로 넘어가기**(가방을 지켜봄): 경비대장이 조각을
  보는 장면이 사라지고, 버리면 되돌아가나 같은 규칙이 생긴다. 저절로 넘어가는 단계는 roadmap B.
- **보상을 모두 단계로**(마지막 단계의 것이 퀘스트 보상): 다음 단계를 보내지 않으니 최종 보상을 처음부터 보일 수 없다.
- **모든 `gives`에 표식**: 계속 쓰는 도구·팔 물건도 준다. **나중 `collect`에 나오면 저절로 표식**: 숨은 규칙.
- **대사를 퀘스트 한 곳에 두고 조건 `stage`로 가르기**(Skyrim 대사 조건, RPG Maker 이벤트 페이지): 한 단계의 이야기가 여러 칸에
  흩어지고, 단계를 끼우면 칸마다 조건을 고쳐야 한다. **단계에 없으면 퀘스트 기본 대사**: 두 곳을 봐야 하는 숨은 규칙.
- **받은 뒤 대사(`taken`)**: 이 이야기는 `ready`에 몰아 적어도 된다. 필요해지면 더하기만 하면 된다(roadmap B).
- **단계를 따라 플레이어도 다른 퀘스트로**: 수락하지 않은 퀘스트가 진행 중이 된다.
