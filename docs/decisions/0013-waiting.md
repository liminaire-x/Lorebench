# 0013 — 기다림: 맡기고 다음 날 찾기

2026-09-27 · 다섯 번째 이야기(대장장이의 내일) 설계(구현 전) · 고치는 비용: **비쌈** (퀘스트 문서의 `wait`·대사 칸,
플레이어 기록의 상태 값 `waiting`과 `handed_` 키, 그래프 `Quest State` 갈래에 남는다. 첫 공개 전이라 지금은 초기화로 쌈)

> 퀘스트 단계(2026-09-27, [0015](0015-quest-stages.md)): `wait`와 대사 `handed`·`waiting`·`ready`는 단계마다 있다. `handed`는
> "건네거나 보여준 직후"로 넓어져 기다림이 없는 단계에서도 쓴다. [받기] 때 그 단계의 `gives`를 준다.

## 장면

> 대장장이에게 철 5개를 건네면 "칼을 벼리는 데 하루는 걸리네. 내일 오게." 그날 다시 가면 "아직 망치질 중일세."
> 자고 일어나 다음 날 가면 "다 됐네!" → 칼을 받는다.

전체 장면은 [stories.md](../stories.md) "다섯 번째 이야기".

## 기다림은 퀘스트의 칸 하나

```json
"goals":   [ { "item": "minecraft:iron_ingot", "count": 5 } ],
"wait":    { "days": 1 },
"rewards": [ { "item": "minecraft:iron_sword[…]" } ]
```

- [건네기] 때 목표 아이템을 가져가고 **기다리는 중**이 된다. 기다림이 끝난 뒤 받는 NPC에게 [받기] → 보상 + 완료.
- `wait`가 없으면 지금처럼 건네는 순간 보상(옛 문서 그대로). `days`는 1 이상, 아니면 publish 거부.
- 단위가 이름(`days`)으로 보인다. 현실 시간은 나중에 다른 이름으로 나란히 더한다(roadmap B "현실 시간 기다림").

## "하루" = 게임 날짜

- `days`는 F3 화면의 `Day` 숫자(`dayTime / 24000`, `DebugScreenOverlay`)가 늘어난 횟수다. 날짜는 **자정이 아니라 아침 6시**
  (`dayTime` 0)에 넘어간다. 잠을 자면 다음 24000의 배수(다음 날 아침)로 뛴다(`ServerLevel`의 `setDayTime(j - j % 24000L)`).
  그래서 `1` = "아침이 한 번 오면", 자고 일어나면 바로다.
- 받아들인 것: 새벽 5시 59분에 맡기면 1분 뒤에 끝난다.
- `/time set day`는 `dayTime`을 1000으로 **통째로** 바꿔 날짜가 0으로 돌아간다(`TimeCommand`). 지금 날짜가 맡긴 날보다
  이르면 **다 된 것**으로 친다(관리자가 시간을 돌렸다고 영영 못 받는 일은 막는다).

## 기록: 상태 `waiting` + 맡긴 날

```
quest_k3f9x2ma        = waiting    (상태, 0005의 active / done 옆에 값 하나)
handed_quest_k3f9x2ma = 12         (맡긴 날의 Day 숫자)
```

- 상태를 `waiting`으로 바꾸므로 `active`를 보는 곳(처치·수확·번식 세기, 조각 떨어지기, J 화면 진행)은 그대로다. 기다리는
  동안은 세지 않고 조각도 떨어지지 않는다.
- **맡긴 날**을 적는다(다 되는 날이 아니라). 작가가 `wait`를 고치면 이미 기다리는 사람에게도 곧바로 적용되고, 날짜가 뒤로
  간 것도 알아챌 수 있다.
- 보이는 상태: 기다림이 끝나면 `ready`. 0005처럼 `ready`는 저장하지 않고 계산한다("지금 받는 NPC에게 가면 끝낼 수 있음").
  그래서 그래프 `Quest State` 갈래와 대사 조건 `questState`는 hidden / active / **waiting** / ready / done.
- 완료(칼을 받음)와 에디터 Players → [Reset]이 `handed_`를 지운다. 선행(`requires`)은 칼을 받아야 채워진다.

## 대사 칸 셋

| 칸 | 에디터 | 언제 |
|---|---|---|
| `handed` | After handing over | [건네기] 직후(`accepted`처럼). 없으면 곧바로 목록(기다리는 줄이 보임) |
| `waiting` | While waiting | 기다리는 중에 받는 NPC에게 말 걸면. 없으면 목록에서 누를 수 없음(`active`와 같은 규칙) |
| `ready` | When it's ready | 기다림이 끝나 [받기] 전. 없으면 바로 카드 |

- 셋 다 조건 묶음(`when`, [0012](0012-lost-necklace.md))을 쓸 수 있다. `complete`는 그대로 "[건네기] 전"이다.
- `ready`는 코드 안의 "건넬 수 있음(READY)"과 이름이 겹치지만, 둘 다 "지금 끝낼 수 있음"이라 뜻이 같다.

## 그 밖 (쌈)

- 다 됐을 때 버튼 **[받기]**(en "Take"), 카드엔 보상만.
- 그래프 `Complete Quest`는 [건네기]/[받기]와 같은 한 걸음: 진행 중이면 가져가고 기다리기 시작, 다 됐으면 보상.
- J 화면은 **"기다리는 중"만**(남은 날은 보이지 않음, 사용자 결정), 다 되면 "받을 수 있습니다".
- 에디터: Needs and rewards에 "Wait [ ] days"(비우면 없음), Players에 `waiting · handed on day 12`.

## 고르지 않은 것

- **퀘스트를 둘로 나누기**(`칼 주문` → 하루 뒤 `칼 찾기`): J 화면에 "칼 주문 완료"가 뜨는데 칼이 없고, 찾을 때 수락·건네기를
  두 번 누른다.
- **퀘스트 단계**(한 퀘스트에 단계 여럿, Skyrim 방식): 이야기가 요구하는 것보다 훨씬 크다. roadmap B "퀘스트 단계"에 적었고,
  그때 `wait`는 "기다리기 단계"로 옮긴다.
- **흐른 틱**(`gameTime`, 24000틱): 잠이 소용없어 "내일"과 어긋난다. **현실 시간**: 게임 속 하루와 무관하다(나중에 더함).
- **상태는 `active` 그대로, 맡긴 날만 따로**: `active`를 보는 모든 곳이 따로 확인해야 해서 하나라도 빠지면 기다리는 중에
  조각이 떨어진다. **한 칸에 합치기**(`waiting:12`): 상태를 읽는 곳마다 글자를 쪼개야 하고 0012(거절 횟수를 따로)와 어긋난다.
- **다 되는 날을 적기**: 작가가 `wait`를 고쳐도 이미 기다리는 사람에게는 안 바뀐다.
- **`"wait": 1`**: 단위가 안 보여 현실 시간을 더할 때 헷갈린다. **`"wait": "1d"`**: 마인크래프트 `/time add 1d`는 24000틱이라
  뜻이 다르다.
- **대사 칸 둘**(`waiting`이 건넨 직후도 겸함): "내일 오게"와 "아직 망치질 중"을 다르게 못 쓴다. **`complete`를 "받기 전"으로**:
  `wait`가 있느냐에 따라 뜻이 바뀌는 숨은 규칙이다.
- **대사 조건 "시간"**: 이 이야기는 시각이 아니라 "기다리는 중이냐"에 달려 있어 필요 없다(0012 "나중에" 그대로).
