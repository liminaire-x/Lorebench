# 0011 — 대화 몸짓: 대화 한 벌과 반복하는 대사 줄

2026-09-27 · 대화 몸짓 설계(구현 전) · 고치는 비용: **비쌈** (NPC 문서·대사 줄의 칸 이름이 저장된다. 첫 공개 전이라
지금은 초기화로 쌈)

## 장면

> 대장장이가 모루에서 망치질을 반복한다(평소). Dev1이 말을 걸자 망치를 내려놓고(들어가기, 한 번) 고개를 끄덕이며
> 말하는 자세를 반복한다(대화). "이 칼 좀 보게" 페이지가 떠 있는 동안 칼을 가리키는 동작을 반복하고, 다음 페이지로
> 넘기면 멈춘다. 대화창을 닫으면 망치를 다시 집어 들고(나가기, 한 번) 망치질로 돌아간다. 옆에 있던 Dev2 화면에서는
> 대장장이가 계속 망치질한다.

## 대화 한 벌: `talk`

```json
{ "id": "npc_…", "name": "대장장이", "model": "smith", "idle": "animation.smith.hammer",
  "talk": { "start": "animation.smith.put_down", "loop": "animation.smith.nod", "end": "animation.smith.pick_up" } }
```

- NPC 문서에 선택 칸 `talk`. 세 칸 모두 비워 둘 수 있고, `talk`가 없으면 대화 중에도 평소 동작 그대로(옛 문서 그대로).
- **들어가기·반복·나가기 한 벌**은 Unreal AnimMontage의 `Start`·`Loop`·`End` 구간, 위처 3 작업 장소·스카이림 가구
  마커의 방식이다. 상태 기계(Unity Animator, Bedrock 애니메이션 컨트롤러)는 에디터에 그림 화면이 따로 필요해 크다.
- 퀘스트 대사가 `lines` 아래에 묶인 것처럼 묶음으로 둔다. 칸 이름은 문서의 다른 칸처럼 한 단어 소문자.
- 앞으로의 방향(roadmap "NPC 일과표·상태"): 평소 동작도 같은 한 벌이 되면 "지금 상태의 `end` → 다음 상태의 `start`"로
  잇는다. 그때 "하던 일 멈추기"(망치 내려놓기)는 `talk.start`가 아니라 평소 상태의 `end`로 옮기는 게 맞다. 문서 내용을
  옮기는 일이고 형식은 깨지지 않는다(`idle`은 글자도 계속 읽는다).

## 대사 줄의 반복: `animation`은 이름 또는 묶음

```json
"active": [
  { "text": "고맙네!", "animation": "animation.chief.happy" },
  { "text": "이 칼 좀 보게.", "animation": { "name": "animation.smith.point", "play": "loop" } }
]
```

- 이름만 쓰면 지금처럼 한 번. 묶음의 `play`는 지금 `loop`(그 페이지가 떠 있는 동안 반복)만 받는다. 마지막 자세 유지
  (`hold`, GeckoLib `thenPlayAndHold`)는 그걸 요구하는 장면이 생기면 값으로 더한다.
- `play`를 `animation` 안에 둔 이유(사용자): 나중에 글자 효과나 소리가 생기면 `play`만으로는 무엇을 재생하는지 모른다.
  글자 효과는 자기 묶음(예: `effect`)을 가진다.
- 반복하지 않는 애니메이션은 늘 이름만 쓰므로 옛 문서 그대로. 모르는 칸·값은 거부.
- 한 줄 안에서 동작을 바꾸는 것("이 밭 좀 보게..." `point` → "헉 해충이 꼬였잖아!" `shocked`)은 타이핑과 함께 **글 안
  표시**로 정한다(roadmap 타이핑 후보). 그때 한 번/반복은 `play`와 같은 말을 쓰고, 줄의 `animation`은 "맨 앞 표시"의 짧은
  형태로 남는다.

## 넘어가는 규칙 (게임 코드, 쌈)

- **말 건 사람 화면에서만**([0009](0009-quest-workbench.md) 대사 줄과 같음). 두 사람이 동시에 말을 걸어도 엉키지 않는다.
- 대화창이 열리면 `start` 한 번 → `loop` 반복(`start`가 없으면 바로 `loop`).
- **첫 페이지는 `start`가 끝난 뒤에** 뜬다(사용자, 조각 2 확인 뒤): 하던 일을 내려놓고 나서 말을 시작한다. 그동안 대화창은
  NPC 이름표만 보이고, 클릭·Space·Enter로 기다림을 건너뛰면 첫 페이지가 바로 뜬다(NPC 동작은 이어지고, 그 줄의
  애니메이션은 `start` 뒤에). Esc는 닫기. 기다림의 상한은 두지 않는다(사용자). `start`가 없거나, 모델 파일이 없어 스티브로
  보이는 화면(애니메이션이 돌지 않음)은 기다리지 않는다. 대화창이 열린 채 이어지는 페이지(수락 뒤 대사)는 기다리지 않는다.
- 줄 애니메이션(한 번)이 끝나면 평소 동작이 아니라 `talk.loop`로 돌아간다. 반복 줄은 다음 페이지로 넘기면 멈춘다.
- 대화창을 닫으면 `end` 한 번 → 평소 동작. `start` 도중에 닫아도 `end`를 재생한다.
- 대화 중 그래프의 `Play NPC Animation`: 끝나면 말 건 사람 화면에서는 `talk.loop`로, 다른 사람 화면에서는 평소 동작으로.
- 동작 사이는 지금처럼 5틱 동안 섞는다.
- 대화 중 **돌아보기**(말 건 사람 쪽으로 몸·머리, 닫으면 원래 방향)도 말 건 사람 화면에서만. 서버가 보내는 방향과
  덮어쓰지 않는 방법은 구현 때 마인크래프트 소스로 확인한다. 저장되는 칸은 없다.

## 고르지 않은 것

- **칸 없이 대사 줄로만**: 줄마다 같은 애니메이션을 달아야 하고, 빠뜨린 줄에서 평소 동작으로 튄다.
- **이름 규칙**(`animation.<모델>.talk`가 있으면 사용): 적을 건 없지만 규칙이 보이지 않고 리소스팩 작가가 이름을 지켜야 한다.
- **따로 놓인 칸**(`talk`·`talkStart`·`talkEnd`, `animationPlay`): 한 단어 소문자 규칙이 섞이고, 앞말을 붙인 칸이 계속 는다.
- **`"loop": true`**: `hold`가 생기면 둘 다 `true`인 줄이 생길 수 있다.
- **처음부터 상태 기계**: 지금 이야기엔 평소 동작이 하나뿐이다. 짝마다 다른 전환은 필요한 짝에만 예외로(roadmap).
