# 0012 — 퀘스트 전용 아이템, 거절 기억, 대사 조건

2026-09-27 · 네 번째 이야기(잃어버린 목걸이) 설계(구현 전) · 고치는 비용: **비쌈** (퀘스트·NPC 문서, 플레이어 기록,
플레이어 가방의 아이템 표식에 남는다. 첫 공개 전이라 지금은 초기화로 쌈)

> 퀘스트 단계(2026-09-27, [0015](0015-quest-stages.md)): `collect`의 `from`은 비울 수 있다(이미 가진 것만 셈, 더 떨어지지 않음).
> "같은 아이템의 `collect` 둘이면 거부"는 한 단계 안에서만 따진다. 단계의 `gives`에 `quest: true`면 같은 표식을 붙인다.

## 장면

> 경비대장이 "늑대가 딸의 목걸이를 물고 달아났네"라며 부탁한다. 거절하면 "그래… 무리한 부탁이지", 다시 오면
> "마음이 바뀌었나?", 다섯 번째로 거절하면 "…자네, 일부러 그러는 거지?". 수락한 사람이 늑대를 잡으면 가끔 목걸이
> 조각이 떨어지는데 그 사람에게만 보이고 그 사람만 줍는다. 셋을 돌려주면 그 뒤로 "목걸이 덕에 딸이 다시 웃는다네."

전체 장면은 [stories.md](../stories.md) "네 번째 이야기".

## 퀘스트 전용 아이템: 목표 `collect`

```json
"goals": [ { "collect": "minecraft:amethyst_shard[custom_name='\"목걸이 조각\"']", "count": 3,
             "from": "kill:minecraft:wolf", "chance": 0.5 } ]
```

- 목표 한 줄이 무엇을(`collect`, `/give` 문법 [0006](0006-item-syntax.md)), 몇 개(`count`), 어디서(`from`), 얼마나 자주
  (`chance`, 0~1, 비우면 1)를 모두 말한다.
- `from`은 진행 기록 키와 같은 `<종류>:<대상>` 모양([0010](0010-farming-goals.md)). 지금은 `kill:`만. 누가 잡았나는 처치형
  목표와 같은 기준이다(길들인 동물·남의 처치는 안 셈).
- **언제 떨어지나**: 그 퀘스트가 진행 중이고, 가방에 있는 **내 조각**이 `count`보다 적을 때만. 한 마리에 하나.
- **주인 표식**: 게임이 조각에 숨은 표식(`custom_data`에 퀘스트 id와 주인)을 붙인다. 목표는 **가방에 있는 자기 표식 조각
  수**로 센다(제출형처럼 저장하지 않고 그 순간 계산). 생존 모드에서는 `custom_data`를 만들 수 없어 위조도 안 된다(0006).
  표식의 모양은 아래 "주인 표식의 모양"(플레이어 가방에 남아 비쌈).
- 건네기 때 자기 표식 조각을 `count`만큼 회수한다.
- **떨어지는 조각**: 죽은 자리에 `lorebench:quest_item` 엔티티(바닐라 떨어진 아이템을 본뜸, 그리기는 바닐라 것을 씀).
  - 주인에게만 보인다: 서버는 엔티티마다 "이 플레이어에게 보낼까"를 묻는다(`Entity.broadcastToPlayer` ←
    `ChunkMap.TrackedEntity.updatePlayer`). 주인에게만 "예"라서 다른 사람 컴퓨터에는 정보가 가지 않는다(자체 퀘스트를
    만든 이유와 같은 원칙).
  - 주인만 줍는다: 바닐라의 "이 사람만 주울 수 있음"(`ItemEntity.setTarget`, 저장 이름 `Owner`, `playerTouch`에서 확인).
  - 5분 뒤 사라짐(바닐라와 같음). 이 엔티티 종류는 월드에 저장되므로 **중간**: 없애도 떨어져 있던 조각만 사라진다.
- 남는 구멍: 호퍼와 몹(여우·알레이 등)은 "주인만" 규칙을 보지 않는다(`HopperBlockEntity`, `Mob.aiStep`). 주인이 죽으면 가방의
  조각은 보통 아이템으로 떨어진다. 어느 경우든 **주인 표식** 때문에 남에게는 쓸모가 없다.
- publish 검사: `collect` 아이템을 읽을 수 있나(0006), `from`의 종류·몹이 있나, `chance`가 0~1인가.

### 주인 표식의 모양 (2026-09-27, 조각 3)

```
custom_data={ lorebench_quest_item: { quest: "quest_necklace", owner: [I; …] } }
```

- `owner`는 마인크래프트가 NBT에 UUID를 쓰는 모양(정수 넷, `NbtUtils.createUUID`). 작가의 아이템에 있던 다른
  `custom_data`는 그대로 두고 옆에 붙인다.
- 키가 `lorebench`가 아닌 이유: 0006이 작가용 숨은 표식으로 `custom_data={lorebench:'…'}`(글자)를 권하므로, 같은 키를
  쓰면 작가의 아이템과 부딪친다.
- 목표는 **표식(이 퀘스트·이 주인) + 아이템 종류**가 맞는 것만 센다. 그래서 한 퀘스트에서 같은 아이템 종류의 `collect`
  목표가 둘이면 publish 거부(서로의 조각을 셀 수 있음). 작가가 나중에 아이템 이름을 바꿔도 이미 모은 조각은 센다.
- 테스트 `QuestItemsTest`. 코드 `QuestItems`·`QuestItemEntity`.

## 거절 기억

```
key   declined_quest_k3f9x2ma     (declined_ + 퀘스트 id, 주인 = 플레이어)
value 3                           (거절한 횟수. 기록 없음 = 거절한 적 없음)
```

- 예/아니오가 아니라 **횟수**: 비용이 같고, 횟수가 있어야 "다섯 번째 거절" 같은 대사가 된다.
- 퀘스트 상태(`active`/`done`, [0005](0005-quests.md))와 **따로** 둔다. 상태에 섞으면 그래프 `Quest State`의 갈래가 바뀐다.
- 수락해도 지우지 않는다. 에디터 Players → [Reset](받기 전으로)은 지운다.
- 이제 [거절]을 서버에 알린다. 서버가 아직 제안 중인지 다시 보고 +1.

## 거절 뒤 대사: `lines.declined`

```json
"lines": { "offer": [...], "accepted": [...], "declined": ["그래… 무리한 부탁이지."], "active": [...], "complete": [...] }
```

- [거절] → `declined` 페이지 → 목록(지금처럼). `accepted`와 짝이고 버튼 이름(decline)과 같은 말.

## 대사 조건: `when` 묶음

대사 칸은 **줄 배열**(지금 모양) 또는 **묶음 배열**이다. 묶음은 **위에서부터 처음 맞는 것**을 말한다(if / else if / else).

```json
"offer": [
  { "when": { "timesDeclined": { "min": 5 } }, "lines": ["…자네, 일부러 그러는 거지?"] },
  { "when": { "timesDeclined": { "min": 1 } }, "lines": ["마음이 바뀌었나? 목걸이 말일세…"] },
  { "lines": ["늑대가 딸의 목걸이를 물고 달아났네."] }
]
```

- `when`이 없는 묶음 = else. 아무 묶음도 안 맞으면 그 칸이 빈 것과 같다(`offer`면 대사 없이 바로 카드).
- 한 `when`에 조건 여럿 = **모두 맞아야**(AND, Skyrim·마인크래프트의 기본).
- 한 칸 안에서 줄과 묶음을 섞으면 publish 거부. 옛 모양 `["…"]`은 조건 없는 묶음 하나로 읽힌다.
- 쓸 수 있는 곳: 퀘스트의 모든 대사 칸, NPC 인사말.
- 표기는 마인크래프트 JSON을 빌린다: 숫자 범위는 `MinMaxBounds`처럼 `{ "min": 5 }`(이상)·`{ "max": 2 }`(이하)·`5`(정확히),
  "이름 → 값" 묶음은 루트 조건의 `"scores": { "이름": 범위 }`처럼. 에디터는 "조건 종류 고르기 + 값" 폼. 모르는 조건 이름은
  publish 거부.

| 조건 | 값 | 쓸 수 있는 곳 |
|---|---|---|
| `timesDeclined` | 범위. 그 퀘스트의 거절 횟수. `declined` 칸에서는 **이번 거절 포함** | 퀘스트 대사 칸 |
| `questState` | `{ "<퀘스트 id>": "hidden" \| "active" \| "ready" \| "done" }`. 값은 그래프 `Quest State`의 갈래와 같은 말(0005). `ready`는 그 순간의 가방으로 계산. 없는 퀘스트는 publish 거부 | 어디서나 |

## 완료 뒤 대사: 새 칸 없이 인사말 조건으로

```json
"greeting": [
  { "when": { "questState": { "quest_necklace": "done" } }, "lines": ["목걸이 덕에 딸이 다시 웃는다네."] },
  { "lines": ["오, 자네 왔군."] }
]
```

- 누가 말하나 = 그 대사를 적은 NPC. 완료한 퀘스트가 여럿이면 작가가 묶음 순서로 정한다. 인사말은 "할 이야기가 없을 때"
  나오므로 제안·건네기가 먼저다. Skyrim도 NPC 인사에 퀘스트 단계 조건을 붙인다.

## 형식·메시지

- 퀘스트·NPC 문서 형식 번호는 1 그대로(새 칸은 없어도 되고, 옛 모양은 그대로 읽힌다).
- 대화·퀘스트 목록 메시지에 칸이 늘어 메시지 버전을 올린다(workflow "메시지 버전").

## 고르지 않은 것

- **퀘스트에 `drops` 칸 + 제출형 목표에 표식**: 작가가 두 곳을 맞춰야 하고, 틀리면 "떨어지는데 안 세지는" 퀘스트가 된다.
- **옮기지 못하게 막기**(버리기·상자·호퍼·번들 금지, 죽어도 안 떨어짐): 막을 구멍이 끝이 없고 다른 모드가 새 구멍을 만든다.
- **보이지만 주인만 주움**(바닐라 `setTarget`만): 싸지만 아직 퀘스트를 받지 않은 사람에게 이야기가 먼저 보인다.
- **가방에 바로 넣기**: 사용자 선택으로 바닥에 떨어뜨림(줍는 맛).
- **한 마리에 여러 개**: 이야기가 요구하지 않음. 강화 아이템 이야기 등이 생기면 `"amount": { "min": 1, "max": 3 }`처럼
  없어도 되는 칸으로 더한다(없으면 1, 옛 문서 그대로).
- **거절 예/아니오**: 나중에 횟수가 필요하면 기록 형식을 바꿔야 한다.
- **`reoffer` 칸**: 조건 묶음의 한 경우(`timesDeclined` 1 이상)라 방법이 둘이 된다.
- **글자 식 조건**(Yarn `<<if $declined >= 5>>`, ink, Dialogue System의 Lua): 읽기 쉽고 "또는"·괄호가 자연스럽지만 작은
  언어 하나를 설계하는 셈이다. 구조로는 길어지는 경우(또는·아님이 섞임)와 못 적는 경우(값끼리 비교, 계산)가 있다.
  자주 필요해지면 그때 다시 정한다.
- **명령어식 범위 글자**(`"5.."`): 짧지만 `{min}` 묶음과 두 문법이 섞인다.
- **퀘스트에 `lines.after`**: 누가 말하나·여럿이면 무엇을 말하나에 숨은 규칙이 필요하다(최근 완료로 고르면 완료 시각 기록까지).
- 이름: `refused`·`decline`(버튼 문구로 읽힘), `quest`·`questDone`(나중에 비슷한 조건과 헷갈리거나 상태마다 이름이 늘어남).

## 나중에 (열어 둔 것)

- 조건 넓히기: "또는"(`any`)·"아님"(`not`), 새 조건 종류(시간, 표식 등), 퀘스트 자체의 `when`(밤에만 제안 등)과 `requires`의
  관계, 인사말의 `timesDeclined`(어느 퀘스트인지 적어야 함).
- `from`의 다른 종류(예: `harvest:`로 밭일하다 나오는 편지).
- `questState`의 다른 쓸 곳: NPC 보이기, 일과표, 머리 위 `!`/`?`.
