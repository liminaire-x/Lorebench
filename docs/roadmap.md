# 로드맵

진행 상태는 **이 파일에만** 적는다. 각 조각은 게임 안에서 확인되는 얇은 단위다.
개념은 [map.md](map.md), 이야기는 [stories.md](stories.md).

## 첫 이야기: 밀 배달 (완성, 2026-09-23)

- [x] **1. 첫 인사**: 새 뼈대(그래프 형식 1, 기록 DB, 노드 4개, 에디터 그래프 목록). CI 그린(테스트 25), 게임 확인 완료(2026-09-23): 첫 접속 인사, 재접속 시 조용함, publish 거부.
- [x] **2. NPC 소환 + 우클릭 채팅**: 에디터 NPC 등록(`npcs.json`) → `/lorebench npc spawn` 배치(기록 DB) → `On NPC Interact`. 서버 이름 설정. CI 그린(테스트 36), 게임 확인 완료(2026-09-23): 소환·이름표·우클릭·무적/고정·여러 배치·재접속 유지·참조 중인 NPC 삭제 거부·정의 삭제 시 사라짐.
  - 알려진 함정: `remove`(가까운 하나)와 `remove <id>`(전부)가 인자 하나 차이라, Tab 자동완성으로 전부 삭제가 실행될 수 있다. 배치 하나를 고르는 방법은 보류(아래 후보).
- [x] **3. GeckoLib 외형**: NPC 정의 `model`·`idle`, 노드 `Play NPC Animation`, 모델 없으면 스티브. 테스트 모델 `chief`(Blockbench MCP, `animation.chief.wave`/`happy`). CI 그린(테스트 39), 게임 확인 완료(2026-09-23): 모델·idle 반복, 우클릭 시 happy 후 idle 복귀, 리소스팩 끄면 스티브.
- [x] **4. 퀘스트 공개 + 퀘스트 화면**: 에디터 퀘스트 작성(`quests.json`), 노드 `Quest State`·`Reveal Quest`, `J` 퀘스트 화면. id를 `<종류>_<무작위>`로 바꿈. 결정: [0004 id·기록 키](decisions/0004-ids-and-record-keys.md), [0005 퀘스트](decisions/0005-quests.md). CI 그린(테스트 53), 게임 확인 완료(2026-09-23): 없는 아이템 publish 거부, 자동완성에 NPC 이름, 공개 전 빈 화면, 우클릭으로 공개, `3/10`·`10/10` 진행과 제출 가능 표시, 밀을 버리면 진행 중으로 복귀, 재접속 유지, publish한 제목 즉시 반영, 참조 중인 퀘스트 삭제 거부, **두 클라이언트(Dev1·Dev2)에서 공개·진행이 각자 따로**.
- [x] **5. 제출 + 보상**: 이야기 전체 완성. 노드 `Complete Quest`, 나갈 때 기록 저장. 결정: [0005 완료](decisions/0005-quests.md). CI 그린(테스트 53), 게임 확인 완료(2026-09-23): 밀 정확히 10개 회수·에메랄드 5개·happy 애니메이션·"고맙네!", 완료 화면(회색·완료·`× 10`), 다시 우클릭하면 "덕분에 살았네"뿐(중복 보상 없음), 가방이 꽉 차면 보상이 발밑에, 나갈 때 기록 저장 후 강제 종료해도 완료 유지, 잘못 연결한 `Complete Quest`는 아무것도 바꾸지 않고 경고.

- [x] **2. 경비대장과 늑대 사냥**: `칼 만들기` 완료자에게만 공개, 늑대를 잡으면 `늑대 1/3`. 처치형 목표([0005](decisions/0005-quests.md)). CI 그린(테스트 60), 게임 확인 완료(2026-09-23): 없는 몹·같은 몹 두 줄 publish 거부, 공개 전 처치는 안 셈, 칼·활 처치가 `1/3`·`2/3`으로 바로 반영, 길들인 늑대·남의 처치는 안 셈, `3/3`에서 멈추고 제출 가능 표시, 목표 순서를 바꿔도 진행 유지, 재접속·재시작 후 유지.
- [x] **3. 사냥 보상**: 대장장이에게 가면 보상. 이야기 완성. 새 코드 없이 에디터(보상·그래프 C 연결)만으로. 게임 확인 완료(2026-09-23): 3/3에서 대장장이에게 보상, 완료 표시(`× 3`), 다시 말 걸어도 보상 없음, 완료 후 처치는 안 셈.

CI 그린(테스트 60), 게임 확인 완료(2026-09-24): 플레이어 선택 기억, ✋로 이름·인챈트·내구도·Gobber 컴포넌트까지 한 줄로, 빈손·접속 안 함 안내, 모루로 이름만 바꾼 가짜는 `0/1`·표식 있는 진짜는 닳거나 이름이 바뀌어도 `1/1`, 진짜만 회수, 태그 목표(`#minecraft:logs`), 잘못된 조건 publish 거부. 기존 `minecraft:wheat` 목표도 예전처럼 퀘스트 완료까지 동작(2026-09-25 확인).
- [x] **데이터 초기화**: Gradle `reset`(콘텐츠·기록을 백업 폴더로). 실행 확인 완료(2026-09-25).
- [x] **한 사람의 퀘스트 되돌리기** (사용자 아이디어, 2026-09-26): 퀘스트 편집 화면의 Players 섹션에 이 퀘스트 기록이
  있는 모든 플레이어(접속 안 한 사람 포함, 이름은 서버의 접속 기록)와 진행을 보여주고, [Reset]으로 그 사람을 **받기 전**으로
  (상태·진행 기록 삭제 → 다시 제안받고 지급품도 다시 받음). 준 보상·지급품은 되가져가지 않고, 다른 퀘스트(이것을 선행으로 둔
  퀘스트 포함)는 그대로. 기록 형식 변경 없음(쌈). `GET /api/quest-players`, `POST /api/quest-reset`(publish처럼 인증 없음).
  기록 저장소에 "이 키를 가진 주인 찾기"(`ownersWith`)·접속 안 한 주인 읽기·쓰기(`peek`·`setAny`) 추가.
  CI 그린(테스트 89), 게임 확인 완료(2026-09-26): 목록에 상태·진행, 접속 중 Reset 시 J 화면 즉시 갱신, 접속 안 한 사람도
  (offline)으로 보이고 Reset 뒤 재접속하면 없음, 다른 퀘스트 그대로, 로그에 기록, Reset 뒤 그래프 공개로 지급품을 다시 받음.

## 작업대: 에디터 나누기 (완성, 2026-09-26)

두 이야기를 만들며 **그래프가 커지는 문제**가 드러났다. NPC 하나가 퀘스트 여럿을 다루면
`Quest State` 안에 `Quest State`가 겹친다(대장장이·경비대장 그래프, 지금은 git 기록에만). 이건 기능이 아니라
**작가(에디터 사용자, 지금은 사용자 본인)의 UX 문제**라서, 플레이어 이야기 옆에 **작가 시나리오**를
두 번째 축으로 둔다.

- [x] **1. 헤더 탭** (완성, 2026-09-25): 탭 모양 → 퀘스트 탭 → NPC 탭. 형식 변경은 퀘스트 폴더뿐.
  - [x] **탭 모양만 먼저**: 헤더에 **Graphs / Quests / NPCs**. Graphs는 지금 화면 그대로, Quests·NPCs는
    UX가 정해지지 않아 **비활성**(마우스를 올리면 "Not designed yet"). CI 그린(테스트 60), 브라우저 확인
    완료(2026-09-25): 탭 표시·Graphs 밑줄, 비활성 탭 클릭 무반응·안내 문구, 기존 편집·Publish 그대로.
    화면 나누기는 아래 제안대로 하되 UX를 정한 뒤에.
  - [x] **퀘스트 탭**: 왼쪽 **트리 사이드바**(폴더·퀘스트, 접기, `+ Folder`·`+ Quest`는 고른 폴더 안에) +
    가운데 **내용**(퀘스트 편집, 폴더 이름·위치·삭제). 폴더는 퀘스트 문서에 저장, 에디터 전용
    ([0008](decisions/0008-quest-folders.md)). 폴더를 지우면 안의 것이 한 단계 위로. Graphs 탭에서 퀘스트 목록은 빠짐.
    마지막 탭은 브라우저가 기억. 코드: `editor/src/QuestTab.jsx`. CI 그린(테스트 62), 게임 확인 완료(2026-09-25):
    기존 퀘스트가 맨 위에 그대로(초기화 불필요), 새로고침해도 탭 유지, 고른 폴더 안에 생성, Folder 선택으로 이동,
    Inside 목록에 자기·하위 폴더 없음, publish 후 새로고침해도 트리 유지, 빈 폴더 이름 publish 거부, 폴더 삭제 시
    안의 것이 위로, Graphs 탭에 퀘스트 목록 없음·노드의 퀘스트 선택은 그대로, J 화면에 폴더 없음·진행 유지.
  - [x] **NPC 탭**: 최대한 간단하게. 왼쪽 NPC 목록(`+ NPC`, 배치 수) + 가운데 이름·id와
    **섹션 카드**(Look: 모델·idle / Placed in the world: 배치 목록·소환 명령). 새 기능은 섹션을 하나씩 더한다
    (Skyrim CK 탭·Easy NPC 탭·Citizens 특성 참고. 특성 붙이기식은 기능이 여럿 생기면). 다음 섹션 후보: 대화(인사말,
    대화창 작업 때), 쓰이는 곳(나중에), 폴더(NPC가 많아지면 퀘스트 트리 재사용). NPC 형식·Java 변경 없음.
    Graphs 탭에서 NPC 목록은 빠짐(노드의 NPC 선택은 그대로). 탭이 모두 켜져 비활성 탭 처리는 걷어냄.
    코드: `editor/src/NpcTab.jsx`. CI 그린(테스트 62), 게임 확인 완료(2026-09-25): 이름순 목록·배치 수, Look·배치
    섹션 표시, 새 NPC publish 후 소환 자동완성, 소환 뒤 새로고침하면 배치 수·위치 반영, 모델 비우면 스티브·되돌리면
    복귀, 그래프가 쓰는 NPC 삭제는 publish 거부, 배치된 NPC 삭제 경고 후 게임에서 사라짐, Graphs 탭에 NPC 목록 없음·
    노드의 NPC 선택은 그대로.
  - [x] **NPC·그래프 폴더**: 퀘스트와 같은 방식으로 `npcs.json`·`graphs.json`에도 폴더 목록(문서마다 따로,
    [0008](decisions/0008-quest-folders.md)). NPC 탭 왼쪽이 트리(`+ Folder`·`+ NPC`, 배치 수). Graphs 탭 사이드바는
    **위아래 2단**: 위 트리(`+ Folder`·`+ Graph`), 아래 노드 팔레트. 폴더를 고르면 오른쪽 칸에 폴더 설정, 그래프
    설정에 Folder 선택. 고른 항목이 든 폴더는 접혀 있어도 펼쳐짐. 트리·폴더 편집은 `editor/src/FolderTree.jsx`,
    서버는 `Folders.java`로 모음. CI 그린(테스트 68), 게임 확인 완료(2026-09-25): 2단 사이드바·기존 그래프 맨 위에
    그대로(초기화 불필요), 고른 폴더 안에 새 그래프가 생기고 열림, Folder 선택으로 이동, 접힌 폴더 자동 펼침, NPC
    폴더·배치 수 유지, publish 후 새로고침해도 세 트리 유지, 그래프 폴더 삭제 시 안의 것이 위로, 그래프 동작(우클릭·

  - Graphs 탭은 그래프 트리 + 노드 팔레트, 캔버스, 노드·그래프·폴더 설정. Publish는 헤더에서 세 문서를 한 번에.
    상태(graphs·npcs·quests·folders)는 Publish 때문에 `App.jsx`에 있다.
- **탭 원칙** (2026-09-25, **열려 있음**: 쓰다가 안 맞으면 고친다. 탭 구성은 에디터 일이라 바꾸는 비용 쌈.
  비싼 건 탭 뒤의 문서를 나누거나 합치는 것):
  - 새 탭은 셋이 **모두** 맞을 때: ① 자기 목록(id가 있고 자기 문서에 저장) ② 자기 편집 화면(캔버스·타임라인·넓은
    폼) ③ 작가가 거기서 오래 일함. 하나라도 빠지면 기존 탭의 **섹션**이나 고르기 목록·팝업으로.
  - 합칠 때: 두 탭이 같은 대상을 편집할 때(예: 몹과 NPC가 둘 다 "모델 + 배치 + 대사"면 "캐릭터" 탭 하나에 종류
    구분), 탭이 너무 비었을 때. 한 작업에 두 탭을 오가면 합치기보다 **고르기 목록·바로가기 링크**를 먼저.
  - 탭이 6~7개를 넘으면 가로 탭 대신 왼쪽 세로 메뉴(VS Code), 전체 검색. 참고: RPG Maker 데이터베이스 탭,
    Blender 작업 공간, Creation Kit Object Window.
  - 적용: **애니메이션**은 애니메이션 파일이 리소스팩에 있고 편집은 Blockbench라 ①·②가 약하다 → 먼저 NPC 탭
    Look 섹션을 넓히고, 몹·뼈대 공유가 생기면 탭(이름은 "에셋"일 수도). **시네마틱**은 **카메라 기능이 필요해질 때**
    추가한다.

### B. 이야기가 끌어와야 하는 것

대부분 문서 형식·기록 키가 바뀌어 비쌈. 멀티서버·리소스팩 자동화처럼 이야기보다 운영(배포)이 끌어오는 것도 여기.

- 거절 뒤·완료 뒤 대사, 퀘스트 전용 아이템: 네 번째 이야기로 옮김. 거기서 미룬 것(조건 "또는"·"아님", 한 마리에 여러 개
  등)은 [0012](decisions/0012-lost-necklace.md) "나중에"·"고르지 않은 것".
- NPC 일과표·상태 (사용자 방향: 규모 있는 멀티 RPG 서버, 2026-09-26): **상태마다 들어가기·반복·나가기 한 벌**을 두고,
  상태가 바뀌면 "지금 상태의 end → 다음 상태의 start"로 잇는다(위처 3 작업 장소 방식). 짝마다 화살표를 그리는
  상태 기계는 피한다. 단계: (1) 대화 한 벌 `talk: { start, loop, end }` → (2) 평소 동작도 한 벌 + 시간대별 일과표
  (`idle`은 글자도 계속 읽어 옛 문서 유지, 대화의 `talk.start`에 넣던 "하던 일 멈추기"는 평소 상태의 `end`로 옮김)
  → (3) 어색한 짝에만 **짝 전환 예외**(기본 잇기 위에 덮어쓰기, Unreal 상태 기계의 짝별 전환과 같은 생각).
  각 단계는 그걸 요구하는 이야기가 생길 때 설계한다. (2)의 숙제: 대화 중에 시간대가 바뀌면, 자리 이동, 누가 같은 자세를 보나.
- 대화 연출 개선 (사용자 제안, 2026-09-26):
  - **타이핑**: 대사를 한 글자씩(언더테일처럼 구간마다 빠르게·느리게). 화면은 쌈, 속도를 대사에 적는 방법(줄마다 칸 / 글
    안의 표시)은 문서에 남아 비쌈. 클릭하면 한 줄을 다 보여주기, 글자 소리는 함께 정할 거리.
    글 안 표시는 **속도와 동작 전환을 함께** 다룬다(사용자 예: "이 밭 좀 보게..."에서 `point` 반복 → "헉 해충이 꼬였잖아!"에서
    `shocked`, Ren'Py `{w}`·`{cps}`, Text Animator의 `<?이벤트>` 같은 방식). 한 번/반복은 줄의 `animation.play`와 같은 말을
    쓴다. 줄의 `animation`은 "맨 앞 표시"의 짧은 형태로 남는다.
  - **대화 몸짓**: 완성, 위 "대화 몸짓" 섹션.
  - **기다리는 동안의 대화창**: A 바구니로 옮김.
  - **빛과 그림자**: 바닐라 렌더러에는 광원에 따른 실시간 그림자가 없고 셰이더팩(Iris 등)이 맡는 영역이라 모드 안에서
    만들기는 매우 어렵다. 셰이더팩과 GeckoLib NPC가 함께 잘 보이는지는 확인하지 않았다. 싼 대안: 발밑 둥근 그림자 크기,
    텍스처에 그려 넣은 명암.
- 퀘스트 단계 (2026-09-27, 다섯 번째 이야기 설계에서): 퀘스트 하나가 **순서 있는 단계의 줄**이 되고, 단계마다 할 일(모으기·
  잡기·기다리기·누구와 이야기하기)과 NPC·대사가 다르다. J 화면엔 퀘스트 하나, 지금 단계의 할 일만 바뀐다(Skyrim 단계 번호·

  번호 기록, 진행 기록을 단계마다 비우나, 그래프 `Quest State`가 단계를 보나. 다섯 번째 이야기의 `wait` 칸은 그때 "기다리기
