# 로드맵

**지금 하는 이야기와 다음 후보**를 적는다. 이야기마다 장면·콘텐츠·조각 상태는 그 이야기의 파일([devlog/](devlog/README.md))에만
있고, 끝난 작업도 거기에 남는다. 개념은 [map.md](map.md).

## 지금 하는 이야기

없음. 여덟 번째 이야기([008](devlog/008-guard-captains-worry.md))까지 끝났고, 다음은 아래 후보에서 고른다.

## 다음 이야기 후보

후보는 두 바구니로 나눈다(2026-09-27). A는 이야기 없이 언제든 할 수 있고, B는 그걸 요구하는 이야기가 생길 때 설계한다.
그래서 "다음에 무엇을 할까"는 사실상 "다음 이야기를 무엇으로 할까"다.

### A. 이야기 없이 해도 되는 정리

알려진 구멍·어색함. 대부분 내부 코드라 쌈.
끝낸 것은 [devlog/tools.md](devlog/tools.md).

- NPC 배치 하나 고르기(보류, 사용자가 **제일 후순위**로 둠 2026-09-27): `remove`와 `remove <id>`가 인자 하나 차이라 Tab 자동완성으로 **전부 삭제**될 수 있다(첫 이야기
  조각 2). 후보는 명령어 분리(`remove` / `clear <id>`), 에디터 배치 목록의 삭제 버튼, 게임 속 관리 GUI(조각 4에서 화면을
  만든 뒤). 배치별 고유 키(`placement_<엔티티 UUID>`)는 이미 있다. 방법을 골라야 한다.
- 에디터에서 문서 검사 미리 보기 (사용자, 2026-09-28, 일곱 번째 이야기 조각 3 확인 중): 단계를 끌어 놓아 `from` 없는 `collect`가
  얻을 길을 잃는 것처럼 문서 검사에 걸리는 일이, publish를 눌러야 긴 영어 메시지로 드러난다. 끌어 놓는 순간 알리는 방법:
  (가) 같은 규칙을 에디터(JS)에도 두기(빠르지만 규칙이 두 곳), (나) 서버에 "검사만" 요청(`POST /api/check`, 저장 안 함)을 두고
  끌어 놓을 때 부르기(규칙은 한 곳, 평범한 HTTP 요청이라 웹소켓 같은 실시간 장치는 필요 없음). 메시지를 알아보기 쉽게(한국어,
  어느 단계인지) 하는 것도 함께 볼 거리. 에디터·웹 코드라 쌈.

### B. 이야기가 끌어와야 하는 것

대부분 문서 형식·기록 키가 바뀌어 비쌈. 멀티서버·리소스팩 자동화처럼 이야기보다 운영(배포)이 끌어오는 것도 여기.

- 거절 뒤·완료 뒤 대사, 퀘스트 전용 아이템: 네 번째 이야기([004](devlog/004-lost-necklace.md))로 옮김. 거기서 미룬 것(조건 "또는"·"아님", 한 마리에 여러 개
  등)은 [0012](decisions/0012-lost-necklace.md) "나중에"·"고르지 않은 것".
- NPC 일과표·상태 (사용자 방향: 규모 있는 멀티 RPG 서버, 2026-09-26): **상태마다 들어가기·반복·나가기 한 벌**을 두고,
  상태가 바뀌면 "지금 상태의 end → 다음 상태의 start"로 잇는다(위처 3 작업 장소 방식). 짝마다 화살표를 그리는
  상태 기계는 피한다. 단계: (1) 대화 한 벌 `talk: { start, loop, end }` → (2) 평소 동작도 한 벌 + 시간대별 일과표
  (`idle`은 글자도 계속 읽어 옛 문서 유지, 대화의 `talk.start`에 넣던 "하던 일 멈추기"는 평소 상태의 `end`로 옮김)
  → (3) 어색한 짝에만 **짝 전환 예외**(기본 잇기 위에 덮어쓰기, Unreal 상태 기계의 짝별 전환과 같은 생각).
  각 단계는 그걸 요구하는 이야기가 생길 때 설계한다. (2)의 숙제: 대화 중에 시간대가 바뀌면, 자리 이동, 누가 같은 자세를 보나.
- 대화 연출 개선 (사용자 제안, 2026-09-26):
  - **타이핑**: 여섯 번째 이야기([006](devlog/006-carrot-thief.md))로 옮김([0014](decisions/0014-typing.md)). 아래는 그 전의 메모. 대사를 한 글자씩(언더테일처럼 구간마다 빠르게·느리게). 화면은 쌈, 속도를 대사에 적는 방법(줄마다 칸 / 글
    안의 표시)은 문서에 남아 비쌈. 클릭하면 한 줄을 다 보여주기, 글자 소리는 함께 정할 거리.
    **글자 소리** (사용자, 2026-09-27): 캐릭터마다 다른 소리(언더테일: 소리가 캐릭터의 특징을 드러냄). 여섯 번째 이야기로 함께.
    거기서 미룬 것: 대사 안에서 **다른 목소리로 바꾸기**(속삭임·해설, 사용자). 표시에 높낮이·크기를 다 적지 않고 NPC 문서에
    이름 붙인 목소리(예: `whisper`)를 두고 `<voice=whisper>`로 부르는 방향. **대사부터 BGM 틀기**(사용자, `<music=…>` 같은 표시).
    글 안 표시는 **속도와 동작 전환을 함께** 다룬다(사용자 예: "이 밭 좀 보게..."에서 `point` 반복 → "헉 해충이 꼬였잖아!"에서
    `shocked`, Ren'Py `{w}`·`{cps}`, Text Animator의 `<?이벤트>` 같은 방식). 한 번/반복은 줄의 `animation.play`와 같은 말을
    쓴다. 줄의 `animation`은 "맨 앞 표시"의 짧은 형태로 남는다.
  - **대화 몸짓**: 완성, [devlog/tools.md](devlog/tools.md) "대화 몸짓".
  - **기다리는 동안의 대화창**: A 바구니로 옮김(끝남, [devlog/tools.md](devlog/tools.md)).
  - **빛과 그림자**: 바닐라 렌더러에는 광원에 따른 실시간 그림자가 없고 셰이더팩(Iris 등)이 맡는 영역이라 모드 안에서
    만들기는 매우 어렵다. 셰이더팩과 GeckoLib NPC가 함께 잘 보이는지는 확인하지 않았다. 싼 대안: 발밑 둥근 그림자 크기,
    텍스처에 그려 넣은 명암.
- 퀘스트 단계: 일곱 번째 이야기([007](devlog/007-necklace-for-the-daughter.md))로 옮김([0015](decisions/0015-quest-stages.md)). 거기서 미룬 것(2026-09-27):
  - **저절로 넘어가는 단계**: 아무에게도 가지 않고, 할 일을 채운 순간 다음 단계로(예: 조각을 주우면 J 화면에 "경비대장에게
    가자"). 단계의 갈 NPC 자리를 쓰는 방식으로 더하면 옛 문서는 그대로. 가방을 지켜보다 버리면 되돌아가나는 그때 정함.
  - **대사 조건이 단계를 보기**: 여덟 번째 이야기([008](devlog/008-guard-captains-worry.md))로 옮김. **그래프가 단계를 보기**는 남김(`Quest State`는 그대로).
  - **받은 뒤 대사 `taken`**: [받기] 직후 한마디(`accepted`·`handed`의 짝). 지금은 `ready`에 몰아 적음.
  - **잃어버린 전용 아이템 다시 받기**: `gives`로 받은 고친 목걸이를 버리면 지금은 Players → [Reset]뿐.
  - **갈라지는 단계**(Witcher 3): 단계에 "다음" 칸을 더하는 방식.
- 현실 시간 기다림 (사용자: 필요해질 것 같다, 2026-09-27): 다섯 번째 이야기의 `wait`는 **게임 날짜**(다음 아침, 잠·`/time`에
  따라 움직임)로 정했다. 현실 시간(실제 N분·N시간 뒤, 서버가 꺼져 있어도 흐르고 서버가 여럿이어도 같음)은 멀티서버·매일
  퀘스트(WoW 일일, 동물의 숲) 이야기가 오면 **다른 단위**로 더한다. `wait` 표기에 단위가 보이게 적어 두면 옛 문서는 그대로.
- 퀘스트 묶음(메인·서브 스토리) (2026-09-27): 퀘스트 여럿을 "메인 스토리 · 1장"처럼 묶어 J 화면에 보이기(Witcher 3 분류,
  FTB Quests 장). 잇기는 이미 `requires`, 묶기는 지금 작가만 보는 에디터 폴더(0008). 단계와는 다른 층이라 따로 더할 수 있다.
- 파티: 파티원 모두에게(대상), 파티가 함께 진행하는 퀘스트(기록의 주인 `party`).
- 도감(Completionist's Index 같은 것): 퀘스트와 같은 "공개" 방식으로 확장.
- 대상 넓히기: 모든 플레이어, 상대방(사건이 역할 이름을 주고 노드가 고름).
- 기다리기(지연): 대사 사이 간격 등. legacy-v2의 틱 스케줄러 참고.
- `Complete Quest`의 `not_ready` 갈래: 기다리기 노드처럼 확인과 완료 사이에 틈이 생길 때 추가. `next`는 그대로라 옛 그래프는 안 깨진다.
- 알림 노드: 화면 오른쪽 위 알림(예: "퀘스트 완료: 밀 배달"). 지금 완료 알림은 그래프의 채팅·애니메이션에 맡긴다.
- 애니메이션 공유: 지금 애니메이션은 모델 이름에 묶임(`animations/npc/<모델>`). **뼈대 규격**(예: `humanoid`)에
  묶으면 같은 뼈대의 모델끼리 공유(Bedrock 분리 파일·Unity Humanoid 방식). 몹 적용은 (가) Lorebench 전용 몹(쌈) /
  (나) 바닐라 몹 교체(GeckoLib `GeoReplacedEntityRenderer`, 한 마리만 바꿀 수 있는지 미확인) / (다) 바닐라 모델 직접
  움직이기(playerAnimator식, 비쌈). 뼈대 이름·파일 경로 규칙은 리소스팩에 남아 비쌈.
- 리소스팩 자동화: Lorebench가 자기 폴더(예: `config/lorebench/assets`)를 항상 켜진 리소스팩으로 등록하면
  모드팩에 Paxi 같은 모드가 필요 없다. 더 나아가 서버가 팩을 호스팅·푸시(이때 에디터 포트 8080을
  외부에 열면 인증 없는 publish API도 열리니 포트 분리나 인증 필요).
- 멀티서버(Velocity): 서버마다 Lorebench, 기록 DB 공유(주인에 서버 이름이 이미 있음). 남은 숙제:
  서버를 옮길 때 기록 순서(나갈 때 저장은 조각 5에서 함. 다만 A가 쓰기 전에 B가 읽는 경합은 남음), 콘텐츠(그래프·NPC·퀘스트 문서)를
  서버마다 둘지 공유 저장소에서 받을지.
- 옛 아이디어 목록: `legacy-v2`의 `docs/ideas.md`.
