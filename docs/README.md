## 문서 규칙

- **같은 사실은 한 곳에만.** 개념은 map, 이야기는 stories, 상태는 roadmap, 비싼 결정의 근거는 decisions.
- **"잠김" 대신 고치는 비용**(비쌈 / 중간 / 쌈)을 표시한다.
- **이야기가 요구하는 것만** 쓴다. 쓰는 곳이 없는 개념을 미리 설계하지 않는다.
- 소유자가 쉬운 말로 설명할 수 없는 결정은 확정하지 않는다.

## 결정 기록 (`decisions/`)

한 주제는 한 파일에서 읽히게 한다(2026-09-27. 참고: adr-tools의 대체·보완 링크, Joel Parker Henderson ADR 모음의
"날짜 붙여 덧붙이기").

- **넓힐 때**: 같은 주제가 넓어지면 날짜·계기를 붙인 섹션으로 **덧붙인다**(예: 0005 "처치형 목표").
- **뒤집을 때**: 결정을 뒤집으면 **새 기록**을 쓰고, 옛 기록 맨 위에 `> 대체됨(날짜, [NNNN](…)): 무엇이 어떻게`를 단다.
  옛 본문은 고치지 않는다(그때 왜 그랬는지가 남게).
- **일부가 바뀔 때**: 다른 기록이 이 기록의 일부를 바꾸면 맨 위에 한 줄 알림 `> 무엇(날짜, [NNNN](…)): …`
  (예: 0001~0006의 "이름 변경", 0005의 "처치 수 기록 키").
- 오타·링크·표현 다듬기는 그냥 고친다.

템플릿(칸은 필요한 것만):

```markdown
# NNNN — 제목

날짜 · 계기(이야기·조각) · 고치는 비용: **비쌈 / 중간 / 쌈** (왜 그 비용인지)

## 장면        ← 이 결정을 요구하는 이야기
## 결정        ← 칸 이름·규칙. 쓴 사실은 출처와 함께
## 고르지 않은 것  ← 다른 선택지와 버린 이유
## <덧붙인 주제> (날짜, 계기)
```
