# 여덟 번째 이야기: 경비대장의 걱정

2026-09-29 · 완성 2026-09-29 · 결정 [0012](../decisions/0012-lost-necklace.md)

## 장면

**NPC가 플레이어가 퀘스트의 어디까지 왔는지 알고 말하는** 이야기. 일곱 번째 이야기의 `목걸이 찾기` 동안 경비대장과 딸의
인사말이 단계마다 바뀐다. 설계는 [0012](../decisions/0012-lost-necklace.md) "단계 조건".

| 플레이어가 있는 곳 | 경비대장 | 경비대장의 딸 |
|---|---|---|
| 받기 전 | 요즘 늑대가 부쩍 늘었어. | 아버지가 요즘 걱정이 많으세요. |
| 1단계(조각 모으는 중) | 딸의 목걸이 일은 잘 되어 가나? | 아버지가 요즘 걱정이 많으세요. |
| 2단계(대장장이에게 가기 전) | 대장장이에게는 가 봤나? | 아버지가 요즘 뭔가 숨기시는 것 같아요. |
| 2단계(맡기고 기다리는 중) | 대장장이 솜씨라면 믿을 만하지. | 아버지가 요즘 뭔가 숨기시는 것 같아요. |
| 3단계(목걸이를 들고) | 어서 딸에게 전해 주게. 기다리고 있을 걸세. | (딸이 받는 NPC라 바로 [건네기]) |
| 끝 | 목걸이 덕에 딸이 다시 웃는다네. | 아버지가 찾아 주신 목걸이, 매일 하고 다녀요! |

- 계기: 인사말 조건이 퀘스트 상태만 봐서, 조각이나 목걸이를 **들고 있으면**(`ready`) 경비대장이 "요즘 늑대가 부쩍 늘었어."로
  돌아갔다. 단계 조건은 진행 중·다 채움·기다림을 가리지 않는다.
- 하루가 지나 목걸이가 다 되면 상태가 `waiting`에서 `ready`로 바뀌므로, 경비대장은 다시 "대장장이에게는 가 봤나?"라고 한다
  (찾으러 가 봤냐는 뜻으로도 읽힌다).
- Dev2는 따로: 같은 순간에도 각자의 단계에 맞는 말을 듣는다.

## 콘텐츠

퀘스트는 그대로, 두 NPC의 인사말만 고친다(위 표).

## 조각

NPC 인사말이 퀘스트의 단계를 아는 이야기. 대사 조건 `stage`.

- [x] **0. 설계** (정함, 2026-09-29): [0012](../decisions/0012-lost-necklace.md) "단계 조건". `"stage": { 퀘스트 id: 단계 id }`, 하는
  중이고 지금 단계가 그것일 때(상태는 안 가림), 없는 단계면 publish 거부, 어디서나, 그래프는 그대로(사용자).
- [x] **1. 단계 조건**: `Speech`의 `stage`(형식 테스트), 서버 계산(`Quests.stageOn`: 받기 전·끝난 뒤·없는 단계면 없음), publish
  검사(NPC 인사말·퀘스트 대사, `namingErrors`), 에디터 조건 폼 "quest stage"(퀘스트 → 그 단계 "1. …", 없는 단계는 빨간
  "(removed stage)"). CI 그린(테스트 140).
- [x] **2. 이야기 조립**: 경비대장·딸 인사말(API로, 넣기 전 문서는 복사). 게임 확인 완료(2026-09-29, Dev1): 수락 뒤 "잘 되어
  가나?", 조각을 든 채(`ready`) "대장장이에게는 가 봤나?"(전엔 "요즘 늑대가…"), 딸 "숨기시는 것 같아요", 맡긴 뒤 "믿을 만하지",
  하루 뒤 다시 "가 봤나?", 3단계 "어서 딸에게…", 끝난 뒤 인사말. 없는 단계를 가리키면 거부: API(`stage_gone0000`)와 에디터
  (3단계를 지우면 빨간 칸 → publish 거부, 로그 `has no stage 'stage_pt7swejw'`), 둘 다 문서 그대로.
