# 개발 일지 (devlog)

Lorebench는 **이야기(구체적인 장면)가 요구하는 것만** 만든다. 여기에는 이야기를 **한 파일에 하나씩** 적는다: 플레이어가
겪는 장면, 필요한 콘텐츠, 조각(게임 안에서 확인되는 얇은 단위)과 그 확인 기록. 지금 하는 이야기와 다음 후보는
[roadmap.md](../roadmap.md), 개념은 [map.md](../map.md), 비싼 결정의 근거는 [decisions/](../decisions/).

각 이야기는 **지금 방식**으로 적는다: NPC와의 대화·퀘스트 흐름은 퀘스트 문서(주는·받는 NPC, 대사)와 대화창이
맡고, 그래프는 콘텐츠로 안 되는 "언제"만 맡는다. 첫·두 번째 이야기는 처음에 그래프(`Quest State` 분기)로
만들었다가 퀘스트 작업대([0009](../decisions/0009-quest-workbench.md)) 뒤 이 방식으로 옮겼다(옛 그래프는 git 기록에).

## 파일

- 이야기: `NNN-영문-요약.md`. 이야기 번호 세 자리(결정 기록의 네 자리와 구별), 영문 소문자와 하이픈. 이름순 = 이야기 순서.
- 새 이야기는 설계(조각 0) 때 파일을 만들고 roadmap "지금 하는 이야기"에 링크한다. 조각의 상태(체크박스)는 **이 파일에만**
  적는다. 끝나면 제목 아래 줄에 완성 날짜를 적고 roadmap에서 링크를 내린다.
- 이야기가 아닌 완료 작업(작가 도구, 에디터, 연출, roadmap A의 정리): [tools.md](tools.md).

이야기 파일의 모양:

```markdown
# N번째 이야기: 제목

시작 날짜 · 완성 날짜 · 결정 [NNNN](../decisions/…)

## 장면     ← 플레이어가 겪는 것
## 콘텐츠   ← NPC·퀘스트·그래프·에셋
## 조각     ← 체크박스, CI·게임 확인 기록
```
