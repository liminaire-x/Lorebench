# Lorebench 지도

> 이 문서는 Lorebench를 **한 장에** 담는다: 무엇으로 이루어졌는지, 각 개념의 쉬운 정의와 고치는 비용.
> 새 개념은 **이야기가 요구할 때만** 더한다. 이야기는 [devlog/](devlog/README.md), 지금·다음은 [roadmap.md](roadmap.md).

## Lorebench가 하는 일

마인크래프트 서버에서 일어나는 일을 **코드 대신 웹 에디터로** 만든다.

```
작가(에디터) ──publish──▶ 서버(검사 → 반영) ──공개된 것만──▶ 그 플레이어의 화면
```

- 작가(운영자)는 에디터에서 NPC를 등록하고, 퀘스트를 쓰고, 필요하면 그래프를 잇는다.
- **Publish**하면 서버가 문서를 검사하고(없는 아이템·NPC, 돌고 도는 선행 등은 거부) 바로 반영한다.
- 플레이어는 NPC와 대화하고, 퀘스트를 받고, 진행을 퀘스트 화면에서 본다.

Lorebench는 **클라이언트+서버 모드**다. 플레이어도 설치한다(NPC 애니메이션, 대화창, 퀘스트 화면 때문).

## 세 가지 재료: 콘텐츠, 로직, 기록

| | 콘텐츠 | 로직 | 기록 |
|---|---|---|---|
| 무엇 | 작가가 쓴 **것**: NPC, 퀘스트 | "X가 일어나면 Y를 한다" | 게임이 **남기는 값** |
| 누가 만드나 | 작가(에디터) | 작가(에디터) | 게임(플레이하면서) |
| 모양 | 문서(`npcs.json`, `quests.json`) | 그래프(노드를 선으로 이음, `graphs.json`) | 기록 DB(주인마다 키 → 값) |
| 예 | 퀘스트 `밀 배달`: 촌장이 주고, 밀 10개를 가져오면 에메랄드 5개 | 처음 접속하면 환영 인사를 한다 | Dev1은 `밀 배달`을 끝냈다 |

- **콘텐츠가 대부분을 맡는다.** NPC와의 표준 흐름(제안 → 수락 → 진행 → 제출)은 퀘스트 문서의 "누가 주고 받나 ·
  무슨 말을 하나"와 대화창이 처리한다. 작가는 퀘스트 하나를 쓰면 된다.
- **로직(그래프)은 콘텐츠로 안 되는 "언제"만.** 첫 접속 인사, 특별한 사건(나중: 퀘스트 완료 때 폭죽 등).
  그래프는 콘텐츠를 **id로 가리키기만** 하고 "무엇을"까지 조립하지 않는다.
- **기록은 게임이 쓴다.** 작가가 쓰지 않고, 같은 콘텐츠라도 플레이어마다 다르다. 형식이 디스크에 남아 비싸다.

## 개념

고치는 비용: **비쌈** = 디스크에 남거나 다른 곳이 가리킴 / **중간** / **쌈** = 내부 코드라 언제든 고침.
공통으로 모든 콘텐츠는 **id**를 가진다: 에디터가 붙이는 `<종류>_<무작위>` 이름표(예: `npc_7ha2m0qe`). 사람은 이름만
쓰고 id는 아무도 고치지 않는다([0004](decisions/0004-ids-and-record-keys.md), **비쌈**).

### 콘텐츠

| 개념 | 쉬운 정의 | 비용 |
|---|---|---|
| NPC 정의 | 에디터에서 등록하는 NPC: id + 표시 이름. `npcs.json`. [0002](decisions/0002-npc.md) | **id·형식 비쌈** |
| 외형 | NPC의 모델·텍스처·애니메이션(GeckoLib). `model`·`idle`이 리소스팩 파일을 이름으로 가리킨다. [0003](decisions/0003-npc-looks.md) | 중간 (리소스팩이 이름 규칙에 기댐) |
| 대화 몸짓 | 말을 거는 동안의 한 벌 `talk`: 들어가기(`start`, 한 번) → 반복(`loop`) → 나가기(`end`, 닫을 때 한 번). 말 건 사람 화면에서만. [0011](decisions/0011-talk-gestures.md) | **칸 비쌈** |
| 목소리 | 대사가 한 글자씩 나올 때 글자마다 나는 소리(NPC 문서의 `voice`, 소리 이름 + 높낮이). 말 건 사람만 듣는다. [0014](decisions/0014-typing.md) | **칸 비쌈** |
| 인사말 | 할 이야기가 없을 때 NPC가 하는 말(NPC 문서의 `greeting`) | **칸 비쌈**, 내용은 쌈 |
| 퀘스트 | 제목·아이콘·본문·보상과 **단계 목록**을 가진 콘텐츠. `quests.json`. [0005](decisions/0005-quests.md) | **id·형식 비쌈**, 내용은 쌈 |
| 단계 | 퀘스트 안의 한 장면: 할 일(`text`)·갈 NPC(`to`, 없으면 주는 NPC)·목표·기다림·주는 것(`gives`)·그 장면의 대사. 차례로 하나씩, 할 일이 없으면 말 걸기. 에디터가 붙인 id(`stage_…`)라 끼우거나 순서를 바꿔도 진행 중인 사람은 제자리, 사람이 있는 단계를 지우면 publish 때 옮길 곳을 고른다. [0015](decisions/0015-quest-stages.md) | **형식·id 비쌈** |
| 주는 NPC, 선행 | 누가 제안하고(`giver`), 먼저 끝내야 할 퀘스트(`requires`). 받는 NPC는 단계마다(`to`). [0009](decisions/0009-quest-workbench.md) | **칸 비쌈** |
| 대사 | 퀘스트: 제안·수락 뒤·거절 뒤. 단계: 진행 중·건네기 전·건넨(보여준) 뒤, 기다림이 있으면 기다리는 중·받기 전([0013](decisions/0013-waiting.md), [0015](decisions/0015-quest-stages.md)) NPC가 하는 말. **한 줄 = 한 페이지**, 줄마다 애니메이션을 붙일 수 있다(대화한 사람 화면에서만). [0009](decisions/0009-quest-workbench.md), [0010](decisions/0010-farming-goals.md) | **칸 비쌈**, 내용은 쌈 |
| 글 안 표시 | 대사 글 속의 꺾쇠 신호: 여기서부터 속도(`<speed>`), 쉼(`<pause>`), 동작(`<play>`·`<loop>`), 소리 끄고 켜기(`<voice=none>`·`<voice>`). 페이지 끝까지, 닫는 표시 없음. 중괄호는 값 넣기 자리로 비워 둠. [0014](decisions/0014-typing.md) | **문법 비쌈** (모든 대사에 남음) |
| 대사 조건 | 대사 칸마다 "이럴 땐 이 말"을 위에서부터 골라 **처음 맞는 것**을 말한다(if / else if / otherwise). 조건: 거절 횟수(`timesDeclined`, 퀘스트 대사에서만), 퀘스트 상태(`questState`), 지금 단계(`stage`, 상태와 관계없이 그 단계에 있으면). 한 묶음 안의 조건은 모두 맞아야 한다. 없는 퀘스트·단계를 가리키면 publish 거부. [0012](decisions/0012-lost-necklace.md) | **이름·모양 비쌈** |
| 목표 | 제출형(`item`, 아이템을 가져옴), 또는 받은 뒤 **직접 한 행동**을 세는 처치형(`kill`)·수확형(`harvest`, 다 자란 작물 포기 수)·번식형(`breed`, 태어난 새끼 수), 퀘스트 전용 아이템(`collect`, 몹에게서 떨어지거나 앞 단계가 준 것). 섞어 걸 수 있다. `keep`이면 보여주기만(가져가지 않음). 단계마다 따로 세고, 단계가 바뀌면 0부터. [0005](decisions/0005-quests.md), [0010](decisions/0010-farming-goals.md), [0012](decisions/0012-lost-necklace.md), [0015](decisions/0015-quest-stages.md) | **형식 비쌈** |
| 퀘스트 전용 아이템 | 그 퀘스트를 받은 사람만의 물건. **주인 표식**(퀘스트 id·주인)이 아이템에 붙어, 몹에게서 떨어지면 주인에게만 보이고 주인만 줍는다. 표식 없는 가짜(`/give`)는 세지 않는다. [0012](decisions/0012-lost-necklace.md), [0015](decisions/0015-quest-stages.md) | **표식 모양 비쌈** (아이템에 남음) |
| 아이템 표기 | 보상·지급품은 `/give` 문법, 제출형 목표는 `/clear` 조건(적힌 부분만 비교, 숨은 표식으로 위조 방지). [0006](decisions/0006-item-syntax.md) | **비쌈** (문서에 남음) |
| 기다림 | 단계를 건넨 뒤 다음으로 넘어가기까지 기다리는 게임 날짜(`wait: { days }`). 날짜는 아침 6시(자고 일어나면)에 넘어간다. [0013](decisions/0013-waiting.md) | **칸 비쌈** |
| 보상 · 지급품 · 주는 것 | 마지막 단계를 끝낼 때 주는 물건(`rewards`) · 받는 순간 한 번 주는 물건(`supplies`, 예: 씨앗) · 단계가 끝날 때 주는 물건(`gives`, `quest: true`면 주인 표식이 붙는 이야기 속 물건, 받기 전엔 안 보임). [0010](decisions/0010-farming-goals.md), [0015](decisions/0015-quest-stages.md) | **형식 비쌈** |
| 폴더 | 에디터에서 NPC·퀘스트·그래프를 묶어 보는 것. 게임은 쓰지 않는다. [0008](decisions/0008-quest-folders.md) | 중간 (문서에 남음) |

### 기록

주인(플레이어 / 서버 `server:<이름>`)마다 키 → 값으로 저장된다. 형식: [0001](decisions/0001-storage-format.md), 키 규칙: [0004](decisions/0004-ids-and-record-keys.md). 모두 **저장 형식 비쌈**.

| 개념 | 쉬운 정의 |
|---|---|
| 표식 | 플레이어에게 남기는 이름표. 예: `flag_greeted`(첫 인사를 받았음) |
| 지금 단계 | `stage_<퀘스트 id>` = 단계 id. 없으면 첫 단계, 끝나면 지운다([0015](decisions/0015-quest-stages.md)) |
| 퀘스트 상태 | 플레이어별: 숨김 → 진행 중 → (기다리는 중) → 제출 가능 → 완료. 단계가 여럿이어도 퀘스트 전체의 상태 하나. 저장은 `active`·`waiting`·`done`뿐이고, "제출 가능"은 그 순간의 인벤토리와 진행 기록으로 계산한다(아이템을 버리면 다시 진행 중). 기다리는 중은 맡긴 날(`handed_<퀘스트 id>`)부터 날짜가 넘어가면 제출 가능([0013](decisions/0013-waiting.md)) |
| 진행 기록 | 세는 목표의 수. `progress_<퀘스트 id>`에 `<종류>:<대상 id>`(예: `kill:minecraft:wolf`)로. 완료하면 지운다 |
| 거절 횟수 | `declined_<퀘스트 id>` = [거절]을 누른 횟수. 수락해도 남고, Players [Reset]이 지운다([0012](decisions/0012-lost-necklace.md)) |
| NPC 배치 | 정의 하나를 월드 여러 곳에 세운 것(메이플 방식, `/lorebench npc spawn`). 서버 기록이 **원본**이라 엔티티는 기록을 따른다 |

### 플레이어 화면

| 개념 | 쉬운 정의 | 비용 |
|---|---|---|
| 공개 | 서버가 **그 플레이어에게 공개된 것만** 보낸다. 공개 전엔 클라이언트에 아무것도 없다 → 스토리 유출 방지(FTB Quests를 쓰지 않은 이유) | 쌈 |
| 대화창 | NPC를 우클릭하면 열린다. 할 수 있는 일(제출 → 새 제안)로 바로 시작하고, 없으면 인사말 + 목록. 수락·건네기는 서버가 다시 확인한다. 대사는 한 글자씩(글 안 표시대로), 클릭하면 한 페이지가 다 보인다. 버튼은 [수락]/[거절], [건네기], [보여주기], [받기]. [0009](decisions/0009-quest-workbench.md) | 화면은 쌈 |
| 퀘스트 화면 | 공개된 퀘스트, 지난 단계(흐리게)와 지금 할 일, 진행(`밀 3/10`, `늑대 처치 1/3`)을 보여준다. 다음 단계는 서버가 보내지 않는다. `J`로 연다 | 쌈 |
| 퀘스트 아이템 툴팁 | 주인 표식이 붙은 아이템 이름 아래 금색 "퀘스트 아이템" 한 줄. 어느 퀘스트인지는 일부러 보이지 않는다 | 쌈 |
| 메시지 | 서버와 클라이언트가 주고받는 것(퀘스트 목록, 대화 내용). 모양을 바꾸면 버전을 올린다([workflow.md](workflow.md)) | 중간 |

#### 에디터 탭

헤더의 탭 하나가 문서 하나를 편집한다. Publish는 헤더에서 세 문서를 한 번에 보낸다.

| 탭 | 무엇을 | 화면 | 문서 |
|---|---|---|---|
| Graphs | 로직(노드 그래프) | 왼쪽 위 트리(폴더·그래프) + 아래 노드 팔레트, 가운데 캔버스, 노드·그래프·폴더 설정 | `graphs.json` |
| Quests | 퀘스트와 그 안의 단계 | 왼쪽 트리(폴더·퀘스트·단계), 퀘스트 카드(Basics·Flow·Dialogue·Supplies and rewards·Players), 단계 화면(Stage·Dialogue) | `quests.json` |
| NPCs | NPC 정의 | 왼쪽 트리(폴더·NPC, 배치 수), 카드(Look·Dialogue·Placed in the world) | `npcs.json` |

**탭 원칙** (2026-09-25, **열려 있음**: 쓰다가 안 맞으면 고친다. 탭 구성은 에디터 일이라 바꾸는 비용 쌈.

  폼) ③ 작가가 거기서 오래 일함. 하나라도 빠지면 기존 탭의 **섹션**이나 고르기 목록·팝업으로.
